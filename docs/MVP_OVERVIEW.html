Recommendation engine

The language model never invents a university. The pipeline is fixed:

Profile -> normalize -> hard filter -> soft exam gate -> 7-factor weighted score
        -> top candidates -> AI explanation (or template) -> final recommendations
FactorWeightWhat it normalises
Budget fit0.25net tuition against the stated budget
Subject match0.22program field against the profile field (related fields score 0.5)
Destination0.15country in the target list
Academic fit0.15GPA and exam scores against requirements
Language readiness0.10language of instruction versus exam evidence
Timeline feasibility0.08months left before the application deadline
Funding available0.05scholarship path when the budget is short

Missing data lowers a confidence badge instead of inventing a value, and the missing factor's weight is redistributed across the known factors. A soft gate drops a program from the main list only when current / required < 0.8 on an exam or GPA, so a failed exam visibly changes the shortlist.

AI layer

WhereInputOutputFallback
POST /api/explainprofile plus already-computed recommendations with their score breakdownstrict JSON: { items: [{ programId, whyItFits, concerns[], nextStepHint }] }template text built from the breakdown, always available and labelled "template" in the UI

Guardrails: the model may only rephrase facts from the input, every returned programId must exist in the request, strings are length-capped, temperature is 0.3, the call times out after five seconds, and any failure silently falls back. The header toggle turns AI on or off; the product is identical without it.
