# DATA_SOURCES.md — политика данных и источников

Правило кейса: **фактические требования и дедлайны должны иметь источники либо быть явно обозначены как демонстрационные данные.**

## 1. Три уровня достоверности

| Уровень | Как помечается | Что показываем в UI |
|---|---|---|
| Подтверждено официальным источником | `Source.kind = "official"`, ссылка заполнена | Ссылка «Источник» + дата обращения |
| Демонстрационные данные | `Deadline.isDemo = true` / `Source.kind = "demo"` | Бейдж <kbd>демо-данные</kbd> |
| Данные отсутствуют | поле не заполнено | «Уточните на сайте вуза» + ссылка |

## 2. Какие источники использовать (по категориям)

| Категория данных | Официальный источник |
|---|---|
| Требования и дедлайны вузов | Раздел Admissions / Приёмная комиссия на официальном домене вуза |
| Стоимость обучения | Tuition & Fees на сайте вуза |
| Английский язык | IELTS (ielts.org), TOEFL (ets.org), Duolingo English Test |
| SAT | College Board (collegeboard.org) |
| Казахстанские экзамены | Национальный центр тестирования (НЦТ), ЕНТ |
| Стипендии | Официальные страницы программ (напр. Bolashak), либо раздел Scholarships вуза |

## 3. Обязательный минимум в `sources.json` для MVP

- 6 вузов × минимум 1 источник на вуз.
- Минимум 1 источник на каждую программу (требования/стоимость).
- Минимум 1 источник для каждого непустого блока `deadlines`.
- Если источник не найден — запись `kind: "demo"` и **бейдж в UI обязателен**.

## 4. Запрещено

- Вписывать конкретный дедлайн или стоимость без источника и без бейджа «демо-данные».
- Давать LLM придумывать или «уточнять» требования, дедлайны, цены.
- Показывать факт как подтверждённый, если источник не открывался.

## 5. Чек-лист перед защитой

- [ ] У каждого вуза в базе есть `sourceIds`.
- [ ] У каждой программы есть `sourceIds`.
- [ ] Все демо-значения помечены `isDemo`/`kind = "demo"`.
- [ ] На экране Sources есть дисклеймер о демонстрационных данных.
- [ ] Ни один факт не «висит» без источника или бейджа.
